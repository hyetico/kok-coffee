# 콕커피 리뉴얼 — 맛 지도 기술서

맛 지도는 이 사이트의 핵심 기능이에요. 이 문서는 맛 지도가 **무엇을 하고, 어떻게 지금 모습이 됐고, 어떻게 계산하고, Next.js로 어떻게 만드는지**를 한곳에 모은 개발 명세예요.

## 0. 문서 안내
| 문서 | 맛 지도에 관해 맡는 것 |
|---|---|
| 02 PRD | 목록 · 취향 테스트 요구사항(무엇을) |
| 03 디자인 가이드 | 목록 화면 배치 · 기기별 크기(어디에) |
| 05 Components | 점 · 핀 · 범례 · 필터(체크 목록 · 슬라이더 · 내 취향 박스)의 색 · 크기(어떻게 보이게) |
| **06 맛 지도 기술서 (이 문서)** | 좌표 · 점수 · 계산 규칙 · 동작 · 상태 · 구현 방법(어떻게 동작하게) |

- 값이 05와 다르면 05가 기준이에요. 계산 · 동작이 다른 문서와 다르면 이 문서가 기준이에요.
- 캔버스 「맛 지도 기술서」 페이지에 이 문서와 함께 실제로 눌러 볼 수 있는 보드(취향 테스트 후 목록 웹 · 모바일, 같은 자리 묶음)를 모아 두었어요.

## 1. 맛 지도가 하는 일
| 할 일 | 사용자가 얻는 것 | 화면 |
|---|---|---|
| 맛 위치로 원두 찾기 | 원두 이름을 몰라도 「고소하고 묵직한 쪽」처럼 위치로 고름 | 목록 · 싱글오리진 · 블렌드 맨 위, 메인 첫 화면 |
| 필터 결과를 지도에서 보기 | 산미 · 바디를 고르면 그 구간이 지도에 상자로 표시되고 나머지 점은 흐려짐 | 목록 |
| 비슷한 원두 찾기 | 점 하나를 고르면 맛이 가장 가까운 원두 3개가 점선 원으로 표시됨 | 목록 |
| 내 취향 위치 보기 | 취향 테스트를 하면 지도에 「내 취향」 핀이 꽂히고 「내 취향과 가까운 순」 정렬이 생김 | 취향 테스트 결과 · 목록 |

- **저장하는 값은 맛 점수 하나**(`taste: { acidity, body }`, 1–5점 · 0.1 단위). 좌표 · 구간 · 글은 모두 점수에서 계산해요. 값을 두 군데 두면 어긋나기 때문이에요.
- 좌표: `x = (산미 − 1) × 25`, `y = (5 − 바디) × 25` (0–100). 상세 페이지 맛 프로필과 같은 점수를 써요.
- 화면 글 「산미 높음 · 바디 가벼움」은 3구간으로 나눈 이름이에요. 바디 묵직 구간은 「바디 묵직함」으로 써요.
- 점은 0.1 단위 점수 그대로 찍어요(2.5 간격). 0.5 단위로 반올림하면 점이 줄지어 겹치고 정도 차이가 사라져요.
- [확인] 지금 점수 21개는 맛 노트를 보고 정한 **임시값**이에요. 실제 커핑 점수가 생기면 `products.json`의 `taste`만 바꾸면 지도 · 필터 · 상세가 함께 바뀌어요.
- 스프링 블렌드(p1)는 로스터가 준 맛 프로필(산미 3.5 · 바디감 3)을 그대로 써요. 그래서 지도에서 가운데 오른쪽에 있어요.
- 상세 페이지 맛 프로필의 「산미」 · 「바디감」 막대는 이 점수를 0.5 단위로 반올림해 보여 줘요. 나머지 항목(단맛 · 쓴맛 · 후미 · 밸런스)은 맛 노트로 계산해요.
- 11-25에 아이리스(p18)를 화사한 쪽(산미 4.4 · 바디 2.7)으로 옮겼어요. 맛 노트가 「화사한 & 과일」인데 고소 · 묵직 쪽에 있었어요.

## 5. 동작
| 하는 일 | 결과 | 닫기 · 되돌리기 |
|---|---|---|
| 점 누르기 | 점 `primary` + 바깥 링 + 이름 말풍선, 맛이 가까운 원두 3개에 점선 원. **아래 목록이 바뀜**: 맨 앞 고른 원두(배지 「고른 원두」) → 거리 가까운 순(가까운 3개는 배지 「맛이 비슷해요」). 목록 위 칩 「○○와 맛이 가까운 순 ✕」, 정렬 이름 「고른 원두와 가까운 순」, 지도에 「목록에서 보기 ↓」 | 칩 ✕ · 같은 점 다시 · 지도 빈 곳 · ESC · 정렬 다시 고르기 |
| 묶음 점(숫자) 누르기 | 묶인 원두 전부가 목록 맨 앞(모두 「고른 원두」), 그 뒤 가까운 순. 칩 「같은 자리 원두 n개와 맛이 가까운 순 ✕」 | 같음 |
| 산미 · 바디 슬라이더 | 지도에 구간 상자, 구간 밖 점 흐림(누를 수는 있음), 목록도 같이 줄어듦. 슬라이더는 연속 범위(낮음–중간처럼 이웃 칸만) | 슬라이더 양 끝으로 · 조건 칩 X · 「초기화」 |
| 향 · 가격 · 디카페인 · 검색 | 맞지 않는 점 흐림 + 목록 줄어듦(구간 상자는 없음) | 같음 |
| 종류 라디오(모든커피) | 지도와 목록 모두 그 종류만 | 「전체」 |
| 「목록만」 | 지도 숨김, 목록만 | 「지도 + 목록」 |
| 키보드 Tab → 방향키 | 지도에 Tab 한 번으로 들어와 ←↑→↓로 그 방향의 가까운 점으로, Enter로 고르기 (10-3장) | Esc · Tab |
| 담기(카드) | 200g · 홀빈으로 담고 토스트 「…장바구니에 담았어요 · 장바구니 보기」 | 토스트 4초(링크가 있어 6초 — 05 기준) |
| 취향 테스트 끝 | 지도에 「내 취향」 핀, 정렬 기본값 「내 취향과 가까운 순」(목록은 줄지 않음), 필터 맨 위 내 취향 박스(「산미 높음 · 바디 가벼움」 · 다시 하기 · 「내 취향으로 거르기」), 안내 멘트 · 뱃지 숨김 | 테스트 다시 하기 |
| 「내 취향으로 거르기」 | 산미 · 바디 슬라이더를 핀이 있는 칸으로 맞춤(`ac = band(pin.x)`, `bd = band(pin.y)`) → 구간 상자 · 흐림 · 목록 줄어듦 · 조건 칩 · 개수 배지. 고른 점 해제. 버튼 글자 「전체 보기」 | 「전체 보기」(산미 · 바디만 전체로) · 슬라이더 직접 · 칩 × · 초기화 |

필터끼리의 관계: **묶음 안은 「또는」, 묶음 사이는 「그리고」**. 예) 산미 낮음 + 중간, 그리고 디카페인.

## 6. 계산 규칙
| 항목 | 규칙 |
|---|---|
| 구간 판정 | `낮음: x < 37.5`, `중간: 37.5 ≤ x < 62.5`, `높음: x ≥ 62.5` (바디는 y로 같은 방식, 작을수록 묵직) |
| 같은 자리 묶음 | 점수가 완전히 같은 원두끼리 묶음(키 `"산미,바디"`). 묶음에 필터를 통과한 원두가 하나라도 있으면 진한 점 |
| 비슷한 원두 3개 | 고른 원두와의 거리 `√(Δx² + Δy²)`가 가까운 순 3개. 같은 자리 원두는 빼요(이미 묶음으로 보이므로). 지금 보이는 종류 안에서만 |
| 고른 원두 목록 순서 | 같은 자리(묶음) 원두 → 나머지를 거리 `√(Δx² + Δy²)` 가까운 순. 필터 밖이라도 고른 원두 자체는 맨 앞에 보여요 |
| 내 취향과 가까운 순 | 핀과의 거리 가까운 순. 거리가 같으면 원래 순서 |
| 취향 핀 | 아래 7장 |

## 7. 취향 테스트 → 지도
5개 질문 중 **1 · 2 · 3번이 핀 위치**, 4번은 결과를 거르는 조건, 5번은 분쇄 안내에만 써요. 시작점은 지도 가운데 (50, 50)이고, 고른 답만큼 움직인 뒤 가장자리에 붙지 않게 12–88 안으로 자릅니다.

| 질문 | 답 | x 이동(화사 +) | y 이동(가벼운 +) |
|---|---|---|---|
| 1. 커피를 주로 어떻게 드세요? | 블랙으로 | +8 | +8 |
| | 우유와 함께 | −10 | −14 |
| | 둘 다 좋아요 | 0 | 0 |
| 2. 가장 끌리는 맛은? | 고소하고 묵직한 | −24 | −22 |
| | 달콤하고 쌉쌀한 | −14 | −14 |
| | 화사하고 과일 같은 | +26 | +14 |
| | 부드럽고 균형 잡힌 | 0 | +4 |
| 3. 산미(신맛)는? | 좋아요 | +14 | 0 |
| | 조금은 괜찮아요 | 0 | 0 |
| | 싫어요 | −14 | 0 |
| 4. 카페인 | 디카페인이 좋아요 | 결과를 디카페인 원두에서만 고름 | |

- 결과 3개: 후보마다 `핀과의 거리 − 0.8 × 맛 키워드 점수(0 이상만)`가 작은 순. 키워드 점수는 답마다 정해 둔 맛 단어가 원두 맛 노트에 있으면 더하는 값(기존 규칙)이라, 거리가 비슷할 때 맛 노트가 더 맞는 원두가 앞에 와요.
- 결과 제목은 핀 구간으로 정해요(예: 산미 높음 + 바디 가벼움 → 「화사하고 가벼운 커피가 잘 맞아요」).
- 「결과 보기」를 누르는 순간 핀을 저장하고(`taste`), 결과의 「맛 지도에서 내 자리 보기」는 목록으로 가요.
- [확인] 이동값은 지도 네 모서리에 골고루 닿도록 정한 값이에요. 실제 사용자 답 분포를 보고 조정할 수 있어요.

// src/lib/taste.ts — 맛 지도 계산 (화면 없이 테스트 가능하게 순수 함수만)
export type Pos = { x: number; y: number }
export const BANDS = { lo: [0, 37.5], mid: [37.5, 62.5], hi: [62.5, 100.01] } as const
export type Band = keyof typeof BANDS
export const inBand = (v: number, b: Band) => v >= BANDS[b][0] && v < BANDS[b][1]
export const acidity = (p: Pos) => Math.round((1 + p.x * 0.04) * 2) / 2   // 1–5
export const body = (p: Pos) => Math.round((5 - p.y * 0.04) * 2) / 2      // 1–5
export const describe = (p: Pos) =>
  `산미 ${inBand(p.x, 'lo') ? '낮음' : inBand(p.x, 'mid') ? '중간' : '높음'} · ` +
  `바디 ${inBand(p.y, 'lo') ? '묵직함' : inBand(p.y, 'mid') ? '중간' : '가벼움'}`
export type Taste = { acidity: number; body: number }   // 1–5, 0.1 단위
export const toPos = (t: Taste): Pos => ({ x: (t.acidity - 1) * 25, y: (5 - t.body) * 25 })
export const dist = (a: Pos, b: Pos) => Math.hypot(a.x - b.x, a.y - b.y)
const key = (t: Taste) => `${t.acidity},${t.body}`
export const nearest = <T extends { id: string; taste: Taste }>(base: T, all: T[], n = 3) =>
  all.filter(p => key(p.taste) !== key(base.taste))
     .sort((a, b) => dist(toPos(a.taste), toPos(base.taste)) - dist(toPos(b.taste), toPos(base.taste)))
     .slice(0, n)
export const groupByTaste = <T extends { taste: Taste }>(list: T[]) => {
  const m = new Map<string, T[]>()
  for (const p of list) { const k = key(p.taste); m.set(k, [...(m.get(k) ?? []), p]) }
  return m
}
const MOVE: ([number, number][] | null)[] = [
  [[8, 8], [-10, -14], [0, 0]],
  [[-24, -22], [-14, -14], [26, 14], [0, 4]],
  [[14, 0], [0, 0], [-14, 0]], null, null,
]
export const pinFromAnswers = (ans: (number | null)[]): Pos => {
  let x = 50, y = 50
  ans.forEach((a, i) => { const m = MOVE[i]; if (a != null && m) { x += m[a][0]; y += m[a][1] } })
  const c = (v: number) => Math.max(12, Math.min(88, v))
  return { x: c(x), y: c(y) }
}

### 배치 방법
- 지도는 `position: relative` 상자 하나에 점을 `position: absolute`로 올려요. 위치는 퍼센트 대신 **안쪽 여백 변수**를 써서 `left: calc(var(--m) + (100% - 2 * var(--m)) * x / 100)`. 기기마다 `--m`만 바꾸면(48 · 32 · 24) 가장자리 점이 잘리지 않아요.
- 점은 모두 `<button>`이에요(지름 14, 누르는 칸은 `::after`로 30까지 넓힘). 묶음 점은 28.
- 구간 상자 · 점선 원 · 핀 · 축은 `aria-hidden` + `pointer-events: none`. 정보는 점의 읽는 이름과 목록에 있어요.
- 「목록에서 보기」 · 뱃지 안을 누르면 지도 빈 곳 누르기로 번지지 않게 `stopPropagation`.
- 그리는 순서(겹침): 축 < 모서리 안내 < 구간 상자 < 점선 원 < 점 < 핀 < 말풍선 · 안내 멘트 < 뱃지 · 「목록에서 보기」.

- 지도 상자: `role="group"`, `aria-label="맛 지도: 왼쪽은 고소한, 오른쪽은 화사한(산미 높음), 위는 묵직한, 아래는 가벼운 맛"`.

### 10-3. 키보드 — 지도는 Tab 한 번, 안에서는 방향키
| 키 | 동작 |
|---|---|
| Tab (지도로 들어올 때) | 점 하나에만 초점(고른 점이 있으면 그 점, 없으면 첫 점). 나머지 점은 `tabindex="-1"` |
| ← ↑ → ↓ | 그 방향 **45° 부채꼴 안**에서 가장 가까운 점으로 초점 이동. 점수 = 방향 거리 + 옆 거리 × 2(옆으로 벗어날수록 불리). 그 방향에 점이 없으면 그대로 |
| Enter · Space | 그 점 고르기 = 아래 목록이 가까운 순으로 바뀜(묶음 점이면 묶인 원두 맨 앞) |
| Esc | 고른 점 해제(목록 원래대로), 초점은 그 점에 |
| Tab (지도 안에서) | 지도 밖 다음 요소로(고른 점이 있으면 「목록에서 보기」로) |

```ts
// components/taste-map/useRovingDots.ts — 핵심만
const DIR = { ArrowRight: [1, 0], ArrowLeft: [-1, 0], ArrowUp: [0, -1], ArrowDown: [0, 1] } as const
export function nextInDirection(cur: Pos, all: { key: string; pos: Pos }[], key: keyof typeof DIR) {
  const [ux, uy] = DIR[key]; let best: string | null = null, score = Infinity
  for (const d of all) {
    const dx = d.pos.x - cur.x, dy = d.pos.y - cur.y
    const along = dx * ux + dy * uy, side = Math.abs(dx * uy - dy * ux)
    if (along <= 0 || side > along) continue        // 뒤쪽 · 45° 밖은 제외
    const s = along + side * 2; if (s < score) { score = s; best = d.key }
  }
  return best
}
// onKeyDown: e.preventDefault() → setFocusKey(next) → 다음 렌더 후 해당 버튼 .focus()
```
- 점 버튼에는 `id`를 붙여 초점을 옮기고, 초점이 들어오면(`onFocus`) 그 점을 현재 위치로 기억.
- 지도 상자: `role="group"` + 읽는 이름 끝에 「방향키로 점 사이를 옮겨요」.
- 확인: 프로토타입에서 Tab → 점 하나 → → ↓ → Enter(목록이 가까운 순) → Esc(해제). 전체 Tab 정지 수가 지도 때문에 1만 늘어나는지.
